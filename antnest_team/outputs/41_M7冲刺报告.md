## 二、M7-1 PRM 多步穿透（全通率攻坚）

### 问题定位
M6 后验：SFT 三元组把多步均值抬到 0.579，但 **multi_pass 仍为 0**——
链式任务在 RL 阶段从未被强化过：GRPO 训练池全是单步零历史任务，
PRM 的过程奖励从未"穿透"到链式场景。

### 解法：多步链展开为逐步训练项
`grpo.py build_multistep_pool()`：复用 SFT 的 10 条多步链规格
（`sft.MULTITURN_SPECS`，模块级常量化），每条链的**每一步**都变成
GRPO 训练项：

```
训练池 = TASK_POOL(32 单步) + 多步池(21 逐步项) = 53 项
每项    = (带历史的 prompt, 期望动作)
prompt  = 任务 + （第N步已完成，使用了 X，结果正常。）继续下一步。
```

- 历史回填格式与 `eval.run_multi_step` / `sft.multiturn_ctx` **逐字一致**；
- 链尾 finish 步同样入池（教模型"何时收工"）；
- PRM 对每步独立打分（L1-L5），组内对比逐步回传——链式任务从
  "见过分布"（SFT）升级为"在分布上被强化"（RL）；
- 回归测试 `test_multistep_eval_separation` 盯防训练链措辞与评测集泄漏。

### 后验
- PRM 训练通过率 0.931 → **1.000**（多步项也全部通过）；
- 评测多步均值 0.325 → 0.342（+5%）——**增益有限**（详见第六节发现3）。

## 三、M7-2 参数级对比学习（L4 攻坚）

### 问题定位
M5 的对比学习负例是"选错工具"（L3），模型对齐后组内奖励已能区分；
但"选对工具、参数键拼写错"（如 grep 的 `path/query` 替代 `p/q`）在
PRM 中仅占 L4 的 0.15 分，组内对比信号弱，模型学得慢。

### 解法：参数键负例对比对
`grpo.py build_param_pairs()`：37 对（每工具任务 + 多步项），
正/负例**同工具、同围栏格式、仅参数键不同**：

```json
正例: {"action": "tool", "name": "grep", "args": {"p": "...", "q": "..."}}
负例: {"action": "tool", "name": "grep", "args": {"path": "...", "query": "..."}}
```

- 负例键表 `PARAM_NEG_ARGS` 覆盖全部 6 工具（语义正确但键名拼写错，
  LLM 生成动作时最常见的参数级错误形态）；
- 与工具级对比（26 对）合并为 63 对总对比池，`λ_ctr=0.3` 联合反传；
- 回归测试 `test_param_neg_args_are_wrong_keys` 保证负例键与
  `TOOL_ARGS` 零交集。

## 四、M7-3 对齐税根治：α 重锚定实验（本冲刺核心突破）

### 问题定位
M4/M5/M6 三次实证同一现象：RL 后 QA 命中率减半（0.167 → 0.083）。
M6 的 α 调度（0.5 → 0.1）没有根治——退火后期锚定减弱，QA 仍被"征税"。

### 解法：α_max 提到 0.7、α_min 提到 0.2、锚定批 3 → 4
grpo9 配置：`--alpha_sft 0.7 --alpha_min 0.2 --anchor_per_iter 4`

```
α(iter 1) = 0.7   # 重锚定：QA 锚定权重比 M6 高 40%
α(iter 30) = 0.2  # 下限翻倍：退火终点不再"放飞"
锚定批     = 4    # 每迭代多锚 1 条 QA 样本
```

### 后验：对齐税首次被根治
| 指标 | grpo8（α 0.5→0.1） | grpo9（α 0.7→0.2） | 变化 |
|---|---|---|---|
| QA 命中率 | 0.083 | **0.167** | **+100%** |
| 动作分 | 0.566 | **0.591** | +4.4% |
| 综合 | 0.434 | **0.475** | **+9.4%** |

**QA 与动作同涨**——历代 GRPO 首次打破"动作涨、QA 塌"的对齐税魔咒，
grpo9 成为历代最优 GRPO 产物。α 调参方向验证成功，代价（策略空间
被压缩）由 M7-1 多步池 + M7-2 参数对的新梯度通路补偿。

## 五、M7-4 轨迹批量积累 + M7-5 语料 v6

### 轨迹批量化：`--batch` 模式
`chat_crew.py read_batch_tasks() / run_batch()`：

```bash
python -m antnest_harness.chat_crew --batch artifacts/batch_tasks.txt
# 批量模式：8 条任务 → 轨迹批量积累
# [1/8] CREW | 工具调用 4 次 | 统计一下团队交付物有多少份
# ...
# 完成：Crew 8 条 / Chat 0 条 | 轨迹 +8 条
```

- 8 条任务全部命中任务路由（回归测试 `test_batch_tasks_are_routed_to_crew`），
  48 次真实沙箱工具调用，轨迹 3 → **11 条**；
- 任务措辞与评测集物理隔离（batch_tasks.txt 首行注明纪律）。

### 语料 v6 与 v7 模型：负边际收益（重要发现）
`corpus.py load_corpus_v6()` = v5 + eval_compare.json（纯指标史）+ chat_log.md
（人机对话日志）→ v7 预训练（25.2M，BPE 5000，best val 7.1866，比 v6 的
7.2164 略优）。

**但下游变弱了**：sft9 综合 0.414 < sft8 0.452，多步 0.325 < 0.438。
归因：chat_log 里的任务型对话稀释了动作围栏分布，预训练 val loss 的
微弱优势无法转化为下游能力——**"运行数据回灌"存在边际收益递减甚至
为负的区间，入库必须筛选而非全量**。这直接回答了 M6 报告遗留问题 #3。

## 六、全链路后验（v7 → sft9 → grpo9 → evo3）

独立评测集（**48 任务**：32 动作 + 4 多步 + 12 QA，与训练物理隔离）：

| checkpoint | 动作分 | pass@3 | QA | 自一致 | 多步均值 | 多步全通 | 综合 |
|---|---|---|---|---|---|---|---|
| sft8（M6 参照，corpus v5） | 0.559 | 0.344 | 0.167 | 0.575 | 0.438 | 0.000 | 0.452 |
| grpo8（M6 参照，α 0.5→0.1） | 0.566 | 0.406 | 0.083 | 0.600 | 0.579 | 0.000 | 0.434 |
| **sft9（corpus v6，+多步池样本）** | 0.506 | 0.312 | 0.167 | 0.675 | 0.325 | 0.000 | 0.414 |
| **grpo9（+多步穿透/参数对比/α 0.7）** | **0.591** | 0.344 | **0.167** | 0.625 | 0.342 | 0.000 | **0.475** |
| evo3（gen3，门禁拒绝） | — | — | 0.083 | — | — | — | 0.414 |

**五个发现：**

1. **对齐税根治**（本冲刺最大突破）：grpo9 QA 0.167 = sft 水平，
   历代 GRPO 首次"零征税"；α_max 0.7 + α_min 0.2 + 锚定批 4 的组合
   成为新的默认配方；
2. **语料 v6 负边际收益**：chat_log 入库稀释动作分布，sft9 全面弱于
   sft8——运行数据回灌需要"入库筛选器"（只回灌工具调用段、过滤闲聊），
   已列入 M8 建议；
3. **多步穿透池增益有限**：PRM 训练通过率到 1.000 但评测多步仅 +5%
   （0.325 → 0.342）——训练分布（模板历史"结果正常"）与评测分布
   （真实观察回填）仍有 gap，且发生在弱 base（v7）上，增益被 base
   退化掩盖；对照 grpo8 在强 base 上 +32%，**多步能力的杠杆仍是 base
   质量**而非 RL 修补；
4. **门禁再次护航**：gen3 轨迹回流增量 SFT 引发过拟合（QA 0.167 →
   0.083，overall 0.475 → 0.414），被回归门禁当场拒绝——进化史 3 代
   中 2 代被拦，**安全网不是过度设计而是必需品**；
5. **多步全通率仍为 0**：链式任务 100% 通过仍未达成，4 条链的最后一
   步（finish 判断 / 参数正确性）仍是断点——M8 需要真实观察回填训练
   （沙箱真实执行结果替代模板历史）。

## 八、M8 建议（按杠杆排序）

1. **语料入库筛选器**：运行数据回灌只取工具调用段 + 动作围栏，过滤
   闲聊对话——修复 v7 base 退化，这是当前最大的单点杠杆；
2. **真实观察回填训练**：多步训练上下文用沙箱真实执行结果替代"结果
   正常"模板——弥合训练/评测分布 gap，直攻 multi_pass=0；
3. **轨迹多样性优先于数量**：gen3 证明 8 条同质轨迹会过拟合，批量
   任务清单需要跨工具、跨参数、跨失败模式覆盖；
4. **LoRA 分头**：动作头 / QA 头解耦训练，从架构上消除对齐税（α 调参
   已到收益上限，QA 0.167 是 25M 模型容量天花板）；
5. **评测方差控制**：25M 模型在 48 任务上单次评测方差大，M8 起关键
   结论应使用多种子均值。
