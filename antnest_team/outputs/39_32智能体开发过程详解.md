# 39 号交付物：32 智能体开发过程详解 —— 他们怎么造出 antNest

> 本文档回答三个问题：**32 个智能体是怎么来的、他们怎么协作开发、每个智能体用什么工具做了什么。**

---

## 一、32 个智能体是怎么来的

蚁巢计划（antNest）的启动材料是 `extracted/` 文件夹中的 **32 份职位说明（JD）文件**（WPS 二进制格式）。团队做的第一件事：

1. **职位提取**：编写脚本解析 32 份 JD 文件，逐一提取职位名称、职责描述、技术栈要求，形成结构化职位清单（`antnest_llm/corpus.py` 的 `jd_titles()` 即来源于此，32 个职位也构成了预训练语料的骨架）。
2. **一一对应建 Agent**：在 `antnest_team/antnest_agents.py` 中，用 **CrewAI 框架**为每个职位创建一个 Agent，`编号 ↔ 职位` 严格一一对应（1 号文件 → agents[1]，…，32 号文件 → agents[32]）：

```python
# antnest_agents.py（节选）
def build_agents() -> dict:
    """构建 32 个 Agent，返回 {编号: Agent} 字典，编号对应职位文件序号。"""
    agents = {}
    agents[1] = Agent(
        role="服务端开发工程师（大模型研究中台/线上核心服务/数据仓库）",
        goal="支撑 antNest 研究中台、面向数千万日活的线上核心服务与数据仓库",
        backstory=("你精通服务端技术与高并发架构，建设模型研究基座平台（可观测、可视化），"
                   "设计大模型应用与 API 服务架构，并用数据管道、离线/实时计算构建下一代数据架构。"),
        ...
    )
    # ……共 32 个，与 JD 文件一一对应
```

3. **任务编排**：`antnest_team/antnest_tasks.py` 定义 **33 个任务（t[1]~t[33]）**，按产品开发真实流程编排：P0 产品定义 → P1 基础保障 → P2 基建与算力 → P3 数据与训练 → P4 Harness 与评测 → P5 运营发布。每个任务指定 `agent=agents[n]`、可依赖上游 `context=[t[m], ...]`、产出写入 `outputs/NN_交付物.md`。
4. **团队入口**：`antnest_team/main.py` 支持结构自检（32 agent / 33 task 校验）、任务清单打印、以及 CrewAI 全量运行：

```bash
cd antnest_team
python main.py --check     # 结构校验
python main.py --list      # 打印 33 个任务
python main.py --run       # CrewAI 全流程运行，产出 37+ 份交付物
```

## 二、协作机制：两层团队

### 第一层：CrewAI 虚拟团队（规划层）
33 个任务通过 `context` 依赖形成 DAG：产品战略（t1）→ 数据中心/采购/财务/法务（t2-t5）→ 集群/算子/框架/存储（t6-t9）→ 运维/网络（t10-t11）→ 数据/预训练/后训练（t12-t16）→ Harness 设计（t17）→ 沙箱与安全（t18）→ 前端/测试（t19-t20）→ 评测体系（t21-t24）→ 跨界创新（t25）→ Frontier 研究（t26）→ 管培生整合（t27）→ 招聘/行政支撑（t28-t33）。每份交付物都是下游任务与训练语料的输入。

### 第二层：工程落地团队（实现层）
规划文档转化为真实可运行的产品代码（`antnest/` 目录）。关键角色在代码中以 `Agent n` 署名注释出现，例如：

| 文件 | 署名 | 职责 |
|---|---|---|
| `antnest_llm/corpus.py` | Agent 3（预训练数据工程师） | 语料收集/清洗/版本化 |
| `antnest_llm/cleaner.py` | Agent 3 | 十六进制噪声剔除 |
| `antnest_llm/bpe.py` | Agent 3/24 | BPE 分词器（训练/保存/加载） |
| `antnest_llm/model.py` | Agent 2/11 | TinyGPT（Decoder-only Transformer） |
| `antnest_llm/train.py` | Agent 24（预训练研究员） | 预训练（warmup+余弦调度） |
| `antnest_llm/sft.py` | Agent 25（后训练研究员） | SFT（41 条动作示例 + 轨迹回流） |
| `antnest_llm/grpo.py` | Agent 18/19 + 25 | GRPO + 五级 PRM + 对比学习 |
| `antnest_llm/eval.py` | Agent 19（评测数据工程师） | 独立评测集（40 任务） |
| `antnest_llm/evolve.py` | Agent 25 + 20 | 在线自我进化闭环 |
| `antnest_harness/agent.py` | Agent 5（Harness 团队） | NestAgent Loop |
| `antnest_harness/tools.py` | Agent 5 + 6 | 工具层 + DSec 沙箱 |
| `antnest_harness/llm.py` | Agent 5 | LLM 抽象层（可插拔） |
| `antnest_harness/chat_crew.py` | Agent 5 + 17 | 对话路由 × Multi-Agent + 轨迹记录 |
| `tests/test_m*.py` | Agent 8（测试开发工程师） | 质量门禁（55+ 项） |

### Harness 内的 Mini 团队（运行层）
`antnest_harness/chat_crew.py` 的 `NestCrew` 在运行时再组成 planner → builder → reviewer 三角色小组，多轮迭代完成用户任务（reviewer 可驳回重做），这本身就是 Multi-Agent 机制的示范。

## 五、如何复现整个开发过程

```bash
# ① 32 JD → 32 Agent → 33 Task 结构校验
cd antnest_team && python main.py --check

# ② CrewAI 团队产出规划交付物（outputs/01-37+.md）
python main.py --run

# ③ 工程落地：全链路训练（详见根目录 README）
cd ../antnest
python -m antnest_llm.train --corpus v4 --tokenizer bpe --prefix v5 ...
python -m antnest_llm.sft  --base_prefix v5 --out_prefix sft7 --traj artifacts/trajs.jsonl
python -m antnest_llm.grpo --base_prefix sft7 --out_prefix grpo7
python -m antnest_llm.eval --ckpt grpo6,grpo7 --passk 3

# ④ 质量门禁（55+ 项）
python -m pytest tests/ -q

# ⑤ 在线自我进化（使用即训练）
python -m antnest_llm.evolve --status
python -m antnest_llm.evolve --force
```

—— 一句话总结：**32 份 JD 孵化 32 个 CrewAI 智能体，智能体规划出 37+ 份交付物，交付物转化为可运行的双产品（antNest LLM + antNest Harness），使用产生的轨迹再回流训练——"蚁巢"由此自我强壮。**
